# План разработки Ghostlink

Цель — один аккаунт на любом наборе устройств: **Android, iPhone, macOS, Windows**.
Ограничения: только бесплатный тариф Firebase **Spark** (без Cloud Functions), без телефона и почты пользователя.

Как устроен проект — в [ARCHITECTURE.md](ARCHITECTURE.md), почему так — в [adr/](adr/).

**Как читать план.** Этап — это GitHub Milestone, пункт `N.M` — Issue и один PR (ветка `feat/N.M-…`). У каждого этапа есть критерий «готово, когда»: этап закрыт, только когда он выполнен и CI зелёный. Сделанные пункты отмечены ✅.

## Этап 6. Push-уведомления и медиа

**Worker.** Без Blaze у проекта нет своего сервера, поэтому всё, что требует секретного ключа, делает один Worker на бесплатном тарифе Cloudflare (без карты): [`worker/`](../worker/README.md), развёрнут на `ghostlink.rangervalera.workers.dev`. Каждый запрос несёт Firebase ID-токен, Worker проверяет его и права пользователя; ключи B2 и сервис-аккаунта лежат только в секретах Worker. Сейчас в нём `POST /media/upload` и `POST /media/download`; по плану добавятся push (6.2), удаление файлов (6.10), копирование при пересылке (7.2), счётчики (8.7) и бот (9.5). Ошибка Worker никогда не мешает отправке текста.

**Файлы.** Firebase Storage требует Blaze, Cloudflare R2 — карту, поэтому файлы чатов лежат в приватном бакете Backblaze B2. Без карты B2 не выставляет счёт, а упирается в лимиты: 10 ГБ хранилища, 1 ГБ скачивания и 2 500 скачиваний (класс B) и 2 500 служебных вызовов (класс C) в сутки. Бакет хранит только последнюю версию файла.

Push:

1. `DeviceDto.pushToken` + правила + тесты правил. Токен пишет `DeviceRegistry` вместе с устройством, источник токена — порт `PushTokens` (на Android — FCM, в демо и на iOS без APNs — нет токена).
2. Push в Worker: `POST /push { chatId, messageId }`. Worker читает сообщение тем же ID-токеном (так проверяются членство и автор), а токены устройств получателей и `chatPrefs.muted` — сервис-аккаунтом проекта (секрет `SERVICE_ACCOUNTS`), и шлёт FCM HTTP v1 data-сообщение: чат, отправитель, начало текста или «Фото». Своим устройствам автора и в заглушённый чат не шлёт; токен, который FCM назвал недействительным, стирает. Лимит частоты против спама.
3. `SendMessageUseCase` и `PhotoSender` после отправки вызывают порт `PushNotifier` в фоне: ошибка Worker только пишется в лог.
4. Android — FCM: `FirebaseMessagingService` обновляет токен и сам показывает уведомление (канал «Сообщения», группировка по чату, нажатие открывает чат). Пока приложение на экране, уведомлений нет; при открытии чата его уведомления убираются. Разрешение `POST_NOTIFICATIONS` (Android 13+) спрашивается на списке чатов.

Медиа:

5. ✅ `MediaStore` в `core:domain` (загрузить, ссылка на скачивание, удалить), реализация через Worker в `core:data`, фейк в `core:testing`. Экраны не знают про B2.
6. ✅ Worker выдаёт подписанные ссылки B2 на загрузку и скачивание после проверки членства в чате; лимит размера и частоты.
7. ✅ `ImagePicker` и сжатие на клиенте: фото до 1280 px и превью 320 px. Лента качает только превью, скачанное кэшируется на диске.
8. ✅ Сообщение с вложением (`attachment`) + правила + тесты правил; превью в пузыре, просмотр на весь экран.
9. ✅ Фото профиля в Firestore (`avatars/{uid}`, до 64 КБ), а не в B2: аватары скачивают чаще всего, в B2 они съели бы лимит скачиваний.
10. Удаление: вложение удалённого или исчезнувшего сообщения удаляется из B2 через Worker (серверных триггеров без Blaze нет).
11. Исчерпанный лимит B2: Worker отвечает понятной ошибкой, клиент показывает «Фото временно недоступно», переписка работает как обычно. Caps & Alerts B2 на 75% и 100% приходят владельцу на почту.

iOS без Apple Developer (push через APNs недоступен, см. «Что понадобится вне кода»):

12. Фоновое обновление `BGAppRefreshTask`: приложение, уходя в фон, просит систему разбудить его не раньше чем через 15 минут. Проснувшись, оно за отведённые ~30 секунд одним запросом к серверу (не из кэша) берёт чаты, обновлённые с прошлой проверки, и показывает локальное уведомление о каждом непрочитанном чате не без звука, где последнее сообщение не своё; время проверки хранится на устройстве. Когда будить, решает система: от 15 минут до нескольких часов, а может не разбудить вовсе (выключено «Обновление контента», режим энергосбережения, приложение смахнули). Это дополнение, а не замена push: с Apple Developer iOS получает FCM поверх APNs по пункту 4, а фоновое обновление остаётся запасным путём. Разрешение на уведомления — на списке чатов, нажатие открывает чат.

**Готово, когда:** сообщение будит закрытое приложение на Android (на iOS без Apple Developer — уведомление приходит при фоновом обновлении, с ним — push); фото, отправленное с одной платформы, открывается на остальных; собеседник видит фото профиля; при исчерпанном лимите B2 переписка продолжается без фото.

## Этап 7. Привычные функции мессенджера

То, что пользователь ждёт от любого мессенджера. Пункты 1, 3–8 — только новые поля Firestore, правила и тесты правил, без Worker.

1. Реакции: `reactions.{uid}` — один эмодзи от каждого участника. Участник меняет только свой ключ, длина ограничена. Долгое нажатие на сообщение, счётчики под пузырём.
2. Пересылка: новое сообщение с `forwardedFrom { name }` без ссылки на исходный чат. Файлы B2 привязаны к чату, поэтому фото копирует Worker внутри B2 (`POST /media/copy`), клиент заново ничего не загружает.
3. Закреплённое сообщение: `chats/{id}.pinnedMessage { id, senderId, preview }`; в группе закрепляет владелец, в личном чате — любой из двоих. Плашка над лентой, нажатие прокручивает к сообщению.
4. Упоминания в группах: `mentions: [uid]`, только участники чата; подсказка после `@`. Чат с упоминанием отмечается «@» даже с выключенным звуком, push (6.2) будит и в заглушённом чате.
5. Поиск: по сообщениям открытого чата — на клиенте, догружая старые страницы (8.5); по названиям чатов и друзьям — в списке чатов. Серверного поиска нет намеренно: после E2E сервер текст не видит.
6. Черновики: недописанный текст хранится на устройстве, не в Firestore. В списке чатов — «Черновик: …».
7. Избранное: чат с самим собой, `chats/{uid}` с `type: saved`. Всегда вверху списка; заметки и перенос фото и текста между своими устройствами.
8. Архив: `chatPrefs.archivedAt`, отдельно от `hidden` («удалён у себя», возвращается с новым сообщением). Архивный чат не входит в счётчик непрочитанных; строка «Архив» вверху списка.
9. Голосовые: запись по удержанию (до 5 минут), AAC/Opus ~24 кбит/с, `attachment.type = voice` с `duration` и волной громкости прямо в сообщении. `AudioRecorder` и `AudioPlayer` в `core:platform`, на десктопе — `javax.sound`.
10. Видеокружки: запись только на Android и iOS, на десктопе — проигрывание. До 60 секунд, H.264 384×384 ~600 кбит/с, превью первого кадра отдельным файлом. Самый дорогой тип для лимита B2 (~400 первых просмотров в сутки на весь аккаунт), при исчерпанном лимите — «Видео временно недоступно» (6.11).

Голосовые и кружки идут после push: на голосовых отлаживается вся цепочка записи и проигрывания, а трафика они берут в 10 раз меньше.

**Готово, когда:** между Android и iOS работают реакции, пересылка с фото, закреплённое сообщение, упоминания, голосовые и кружки; десктоп проигрывает голосовые и кружки; черновики не создают записей в Firestore.

## Этап 8. Готовность к настоящим пользователям

То, без чего приложение отклонят в App Store и Google Play или без чего оно сломается при первых десятках пользователей.

1. Блокировка и жалоба (правило Apple 1.2): `users/{uid}/blocked/{otherUid}`, заблокированный не пишет в личный чат и не добавляет в группы; чат пропадает из списка. Жалоба — `reports/{id}`, читает только владелец проекта в консоли.
2. Удаление аккаунта в приложении (Apple 5.1.1(v), Google Play): профиль, устройства, `chatPrefs`, свои сообщения помечаются удалёнными, затем аккаунт Firebase на всех устройствах.
3. Минимальная версия: `config/app` с `minVersion` по платформам, экран «Обновите приложение». Делается до того, как ужесточать `firestore.rules`, иначе старые клиенты ломаются молча.
4. Квоты Spark (20 000 записей и 50 000 чтений в сутки): heartbeat присутствия реже и только при открытом приложении, троттлинг «печатает…», расчёт расхода на активного пользователя в ARCHITECTURE.md.
5. Пагинация ленты: сейчас грузятся последние 300 сообщений, старые подгружаются при прокрутке вверх.
6. Политика конфиденциальности (GitHub Pages) и Data Safety для Play.
7. Мониторинг лимитов (Spark не шлёт предупреждений, бюджетные алерты Google Cloud требуют платёжный аккаунт):
   - ежедневный GitHub Action забирает из Cloud Monitoring API чтения, записи и удаления Firestore и падает выше 75% квоты — GitHub присылает письмо. Сначала проверить, что API отдаёт эти метрики на Spark;
   - Caps & Alerts B2 на 75% и 100%;
   - Worker считает загруженные байты и выданные ссылки и отдаёт их владельцу на `GET /stats`; Action добавляет их в отчёт.
8. Уборка:
   - еженедельный GitHub Action (Admin SDK) удаляет файлы B2 без сообщения, истёкшие `linkRequests`, старые «надгробия» сообщений и устройства, не заходившие полгода. Порциями ночью: удаления тратят ту же квоту записей;
   - lifecycle-правило B2 для старых медиа (например, 180 дней); клиент показывает «Файл больше не хранится»;
   - лимит дискового кэша медиа (500 МБ, вытесняются самые давние) и «Очистить кэш» в настройках.

**Готово, когда:** заблокированный не может написать (тест правил); аккаунт удаляется из приложения; старая версия видит экран обновления; 50 активных пользователей в день укладываются в квоты Spark; превышение 75% любой квоты приходит письмом; сироты в B2 удаляются без ручной работы.

## Этап 9. Релиз

1. CI по тегу `v*`: AAB/APK, `.dmg`, `.msi`, iOS-сборка → GitHub Releases.

3. Дистрибуция: GitHub Releases, по желанию Google Play и TestFlight.

5. Бот Ghostlink — системный чат `chats/bot_{uid}` (`type: bot`) вверху списка, с галочкой ✓. Сообщения бота пишет только Worker (`POST /bot`) через REST Firestore от сервис-аккаунта; клиент не может создать такой чат или писать от имени бота (правила + тесты правил). Нужны push (6.2), счётчики (8.7) и сборки (9.1).
   - «Лимиты»: владелец (`OWNER_UID`) видит расход Firestore, B2 и Worker, остальные — «Фото и видео работают» или «Лимит исчерпан до 03:00».
   - «Скачать APK»: ссылка на последний GitHub Release (только в Android-сборке не для Play), на iOS — TestFlight.
   - Объявления о релизе и статус медиа — одной записью в `botFeed`, а не в каждый чат, чтобы беречь квоту записей.
   - По cron Worker бот присылает владельцу отчёт за сутки и предупреждения на 75% и 100%. Если исчерпана квота записей Firestore, бот написать не сможет — запасной канал остаётся письмо от Action (8.7).

## Этап 10. Сквозное шифрование (E2E)

Ключ аккаунта уже одинаковый на всех устройствах (его передаёт привязка), поэтому из него выводится постоянная пара ключей аккаунта, и синхронизировать ключи между устройствами не нужно. Цена простоты — нет forward secrecy: утечка ключа аккаунта раскрывает всю переписку. Это не протокол Signal, и README должен говорить об этом прямо.

1. `core:crypto`: пара X25519 из ключа аккаунта через HKDF; публичный ключ в `users/{uid}.publicKey` + правила + тесты правил; test vectors для всех платформ.
2. Личные чаты: ключ чата = ECDH двух публичных ключей → HKDF; `text`, `replyTo.preview`, `pinnedMessage.preview`, `forwardedFrom` и `lastMessage` шифруются AES-256-GCM, id сообщения входит в AAD.
3. Группы: ключ группы создаёт админ и раздаёт участникам, зашифровав ключом личного чата с каждым; при удалении участника ключ меняется.
4. Вложения шифруются на клиенте до загрузки в B2.
5. Проверка собеседника: код безопасности (отпечаток публичных ключей) в профиле, сравнение при встрече или по QR.
6. Переход: старые сообщения остаются открытыми и помечаются; push показывает «Новое сообщение» без текста.

**Готово, когда:** в консоли Firestore и в B2 нет открытого текста новых сообщений и файлов; переписка читается на всех платформах аккаунта; коды безопасности двух собеседников совпадают.

## Сознательные ограничения

- До этапа 10 нет сквозного шифрования, а в этапе 10 оно без forward secrecy.
- Нет звонков: для WebRTC нужен TURN-сервер, бесплатно надёжно не поднять.
- Отзыв отдельного устройства мягкий; жёсткий — только «выйти на всех устройствах» (смена пароля).
- На десктопе нет push, только уведомления запущенного приложения.
